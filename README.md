# Auralis

A private cloud photo library: upload photos, organise them into albums, favourite or archive them, and browse them in a fast, keyboard-friendly gallery. Photos are stored in your own AWS account.

## Features

- Gallery, album, favourites and full-screen viewer pages, with animated page transitions that respect reduced-motion settings
- Drag-and-drop uploads straight to S3 through presigned URLs, so files never pass through the API server
- Automatic WebP thumbnails, generated by an S3-triggered Lambda
- Albums, tags, favourites, archive and soft delete
- A dashboard with storage usage and library stats
- A command palette and keyboard shortcuts
- Per-user settings: theme, gallery density, sort order and upload quality

## Architecture

| Part | What it does |
| --- | --- |
| `src/` | React 19 + TypeScript + Vite frontend, styled with Tailwind, animated with Framer Motion and GSAP, data via TanStack Query |
| `server/` | Express + TypeScript API: auth, photos, albums, uploads and dashboard routes |
| Amazon Cognito | Sign-up and sign-in; the API verifies Cognito JWTs against the pool's JWKS |
| Amazon S3 | Two private buckets, one for originals and one for thumbnails; reads go through short-lived signed URLs |
| AWS Lambda (`lambda/thumbnail`) | Resizes each new original to a 720px WebP thumbnail with `sharp` |
| MySQL on Amazon RDS | Users, photo metadata, albums, tags and settings (`server/src/db/schema.sql`) |

The frontend talks to the backend through a service adapter. `VITE_DATA_ADAPTER=mock` runs the whole UI on local mock data, and `VITE_DATA_ADAPTER=aws` points it at the real API.

## Running locally

Frontend only, on mock data:

```bash
cp .env.example .env
npm install
npm run dev
```

With the API (needs the AWS resources below):

```bash
cd server
cp .env.example .env   # fill in the Cognito, S3 and RDS values
npm install
npm run dev
```

Then set `VITE_DATA_ADAPTER=aws` and `VITE_API_URL=http://127.0.0.1:4000` in the frontend `.env`.
